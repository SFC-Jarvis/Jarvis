## 何を残すか
残すのは、**判断や方針を決めたプロンプト**と、**作業を指示したプロンプト**だけ。

- 残す: 方針の決定（例: 「Ollama は Windows の PC だけで使う」）、作業の指示（例: 「/report の md をダウンロードフォルダに保存するようにして」）、仕組みの変更、不具合の報告と修正の指示、カスタムコマンドの使い方の工夫
- 残さない: 確認のための短い質問、要約の依頼、言い換え・語尾の調整、「はい」「進めて」などの返事、設定画面の選択肢を 1 つずつ聞いただけのもの
- 同じ目的の短いやりとりが続いたときは、1 件にまとめる

例（残すプロンプト）:
> please create a document that keeps track of a summary of all influential prompts that were asked to formulate these idea documents, omitting unimportant prompts like clarifying questions, summary demand, rewording, etc.

## 記録の形
教員が後から読んで、**どんな判断を Claude と一緒にしたか**が分かるようにする。1 ファイルは次の順に並べる。

1. **概要**: 使ったもの・使い方の型・記録の出どころ・カスタムコマンドの利用回数
2. **全体の流れ**: 日付・テーマ・主な判断や成果・PR の表。1 画面で全体が分かる長さにする
3. **記録**: 分類ごとの節に分け、節の中は日付順にする
   - 分類: 1. 企画・設計 ／ 2. 開発の土台づくり ／ 3. タスクの実装 ／ 4. 開発体験の改善 ／ 5. 計画の変更・チーム運営 ／ 6. この記録をつくる（該当がない節は作らない）
4. **Claude の使い方で工夫したこと・気づいたこと**: 振り返り。うまくいった頼み方や、Claude の誤りへの対処

各記録は次の形にする。

```markdown
#### <日付>　<タスク ID（あれば）>　<目的>（<Claude アプリ / Claude Code・PC>）
- 指示: <何を頼んだかの要約。日本語で 1〜3 文>
- 結果: <何が決まり、何ができたか。PR があれば番号>
```

方針を決めた**代表的な指示だけ**、「指示」の行の代わりに原文を抜粋して載せる。

```markdown
> <原文の抜粋。長いときは要点の文だけにして「（以下略）」>
>
> 【自動翻訳・原文は英語】<日本語訳。原文が日本語なら、この 2 行は書かない>
```

- 「指示」の要約と「結果」は日本語で書く。原文は原文の言語のまま書く
- **原文が日本語以外なら、Claude が日本語に訳し、原文のすぐ下に `【自動翻訳・原文は英語】` の印を付けて置く**（英語以外なら「原文は〇〇語」）。訳の言い回しが不自然でも、翻訳によるものだと分かるようにするため。意味が食い違うときは原文が正。訳は直訳に近くし、補った言葉は入れない
- 同じ目的のやりとり（質問・直しの指示・`/sync` などの操作）は 1 件にまとめる
- トークン・API キー・パスワード・個人のデータ・メンバーの名前は**書かない**（伏せるのではなく、その部分を省く）。このリポジトリは公開されている
- `/done` を実行すると、Claude がそのセッションの重要な指示を、該当する分類の節に追記し、「全体の流れ」の表も更新する（ユーザーが確認してからコミット）

## 過去の記録を集めるとき
`/done` での追記より前の記録は、各自が手元の Claude（Claude アプリ・Claude Code）に「この会話（または `~/.claude/projects/` の会話記録）から重要なプロンプトを一覧にして」と頼んで集め、自分の記録に統合する。
